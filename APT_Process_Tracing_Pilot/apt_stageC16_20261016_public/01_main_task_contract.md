# 第四研究内容：主任务工作合同（C16）

已确认任务：从给定下游可疑事件 B，在含正常背景的原始主机/网络事件中，追查可支持的上游攻击来源候选及其到 B 的证据路径。依据是用户规划 U1 与用户提供的执行合同 U2；本轮 U0 再次要求核对这一主线。它是工作任务，不是已确认的最终论文标题。

|层次|输入与输出|与第四项的界线|
|---|---|---|
|A 攻击检测／研究一|PCAP→攻击/正常|回答是否有攻击，不负责来源路径|

可计算合同：输入(B, E[合法范围], 实体/关系schema, 固定预算)；输出(来源候选集合Â, 每候选→B的有向路径/子图, 每边原记录定位/类型/可信层级, 缺失或截断边界)。B由发布者记录独立选定并映射为原事件，标REFERENCE_SEEDED_QUERY；不是在线检测性能。B-only仅限制种子，允许读取同范围全部正常及上游事件，禁止给检索器参考A、攻击全链、答案IOC清单、计划脚本或Gold派生排名。

本轮实体层级建议（CURRENT_AGENT_INFERENCE；PROPOSED_NOT_USER_CONFIRMED）：以入站连接/会话实例为来源，进程/文件是路径中间实体。键需hostId、NetFlowObject UUID及可支持生命周期的连接事件；五元组/IP单独不能证明同一连接。若数据无法区分会话，输出SOURCE_INSTANCE_UNRESOLVED，不悄悄退化为恶意IP、最早日志、init进程或组织归属。报告中的Nginx入站场景支持选此层级，但该执行的具体连接仍未映射。

候选空间为窗口内有合法有向证据链到B的入站实例；A的等价集合只由独立发布记录与原事件消歧建立，不能因同IP/时间近便视为等价。路径分别保留SENSOR_EXECUTION_DEPENDENCY、MAY_INFORMATION_FLOW、SAME_SESSION、TEMPORAL_CONTEXT；后两类单独不构成传播边。进程必须区分UUID/生命周期，文件须区分对象及版本边界；跨主机只在会话与时钟证据实际支持时纳入。长期同进程状态只能标保守可能关系。

按(node,时间上界)逆向查询，真实边仍按信息/执行方向保存。到窗口外父节点、身份未解、缺事件或预算即停，标截断；不可达仅对已读范围成立。边界输出不是成功定位来源。无真值时不算Top-k/MRR或路径P/R，不把遍历次序当排名。
