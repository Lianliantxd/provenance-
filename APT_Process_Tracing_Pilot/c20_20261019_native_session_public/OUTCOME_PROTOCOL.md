# Outcome rules and limits

A session-level reference and a transport-level reference are evaluated separately. The accepted unit is an observed receiving remote-execution context, scoped by native runspace/host identities and a corroborated receiving process instance. A network logon alone, repeated process name, shared account, port, tuple, or nearest timestamp cannot qualify it.

The process-to-shell bridge uses the module provider's emitting PID, exact recorder host, native context, and multi-field process-creation/lifetime corroboration. Engine lifecycle records with unavailable emitting PID connect through their actual runspace/host identifiers. The endpoint is bound through the exact parent process identity. Competing observed receiver contexts and all selected logons are retained. No direct per-pipeline command identity or complete attack-path ground truth is claimed.

Logon IDs are confined to the observed process-execution interval. Boot identity is not independently available; cross-boot reuse is not silently accepted. Provider namespaces are not equated merely because both fields are named GUID. Raw top-level missing fields are distinguished from actual values parsed from named context sections. Character spans preserve the parsing basis. A standard endpoint configuration label is not promoted to a unique session ID.

Only frozen native targets were saved and adjudicated. Reading the whole member to EOF proves this pass's integrity, not logging completeness or a qualified candidate universe. Unzoned operation times retain their uncertainty; collection timestamps do not become causal clock estimates. No future observations were handed to a running method.

The session reference remains evaluator-only. A uniformly defined observable candidate universe, a lawful historical method view, and independent evaluation isolation are still required before ranking. Direct native session-to-connection evidence is separately needed for a transport claim. No next stage is started automatically.
