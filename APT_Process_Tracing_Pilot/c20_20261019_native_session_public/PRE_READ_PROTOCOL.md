# Pre-read limits and evidence rules

One existing ZIP member, one sequential pass, up to 3 GiB delivered uncompressed bytes, 800000 event parsing attempts, 3600 seconds, 4 GiB supervised RSS, 256 MiB new output and one CPU worker. These are proposed authorized ceilings, not measured usage. No new download, source mutation, attack, model or GPU execution.

The reader uses 64 KiB delivery chunks and a 16 MiB record-line safety limit. It parses JSON objects rather than executing text. Chunk boundaries, nested objects, Unicode, escapes, EOF, truncation, non-target accounting and limits are tested. An early stop never becomes a full-member EOF or complete CRC claim. Original timestamps stay distinct; an unzoned time receives no invented causal offset.

A successful network logon, repeated process name, or matching five-tuple cannot create a remote-shell identity. Instance scope, receiving lifecycle, inbound control, independent endpoint binding, original locators and competitors must all be established. No A2 handoff exists during preparation.

Approval is separately required by the user's stage contract. Preparation code and target/configuration digests are frozen before approval and extraction.
