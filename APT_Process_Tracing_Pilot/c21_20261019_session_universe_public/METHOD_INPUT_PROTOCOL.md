# Historical input and reference separation

The query event, receiving-runspace unit, thirty-minute native lookback and cutoff are fixed before candidate generation. Discovery enumerates all actual event types of the declared scripting/remoting providers on the query host. A previously documented collection/fallback retrieval envelope serves recall auditing only; it cannot extend historical eligibility.

Native occurrence time and collection/ingestion time are separate. Unzoned native times retain uncertainty. Online admission requires proof of pre-cutoff occurrence and availability. Retrospective admission requires a comparable pre-cutoff native clock and is never an online claim. A later module event cannot complete an earlier partial identity inside a historical view.

The retained raw cache was reference-conditioned in an earlier stage. It is joined only by independently enumerated locations/hashes. Missing peers remain explicit gaps, and selective cache richness cannot grant one candidate extra method-visible identity. Query completion, native-byte coverage, session identity completeness and candidate-universe completeness are distinct statuses.

The generator accepts only explicit input paths and a read-only database URI. Reference paths are denied by a Python audit hook; a separate evaluator opens the reference only after output hashes freeze. This provides auditable process/input separation, not an OS security boundary or blind human analysis. Synthetic reference replacement does not change observation-derived results. Real candidate generation was not repeated after evaluation.

Difficulty uses only the query's parent identity and legal candidate receiver identities. More than one candidate does not establish difficulty when a direct equality join already resolves it. Diagnostic-only future/untimed contexts remain separate. All unknown competitors are unlabeled; no metrics are computed without admission.
